### Reproducible Blender intake and clinical gate

For a newly approved candidate, retain the **original** downloaded file outside the public repository initially; record original URL, exact creator, per-item license and version/DOI, download UTC, original file byte count and **SHA-256**, and whether there are privacy/consent implications. Record Blender version and exact transformations including import axis, unit scale, root transform, mesh split/merge operation, texture conversions, remesh/decimation settings and derived asset hash. Do not overwrite original model bytes.

In Blender, inspect **occlusal, buccal/labial, lingual/palatal, mesial/distal, and root/apical** viewpoints as relevant, plus wireframe/non-manifold edges. For a full dental arch, report object count, connected components, named teeth and **exact FDI mapping**; for tissues, report enamel/dentin/pulp/PDL/bone as *separate* only if real imported surfaces or solids support them. For instruments, check units, scale, origin, grip, collision, proper articulated nodes and material appearance. Render both a neutral turntable and feature-specific images in an immutable new review folder. Record all errors rather than hiding mesh artifacts by smoothing.

**Clinical review status remains `NOT_VALIDATED` for every source**, including the existing Dundee surface set. A scientific asset/source license does not certify precision for cavity preparation, endodontic access, occlusion, periodontal mechanics, treatment or assessment. One patient's scan is not an average or normative atlas. An approved *visual prop* must not automatically graduate to a *clinically meaningful simulation mesh*.

### Publication rules

Only upload new third-party mesh binaries or derived previews after **(1)** per-item permission explicitly covers redistribution under the intended repository terms, **(2)** original bytes and SHA-256 are preserved and independently checked, **(3)** Blender geometry/appearance is actually inspected, **(4)** attribution, modifications and any share-alike/noncommercial restrictions are committed beside each binary, and **(5)** FDI and clinical limitations are visible in the UI. For private/personal-use only, assets with NC conditions may be considered subject to their exact terms; this does not automatically make all public redistribution permitted. For sources with a blank/ambiguous license, or downloaded files not independently audited, keep **metadata and source links only** on public GitHub.
